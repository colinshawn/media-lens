## Why

调用方需要把公开分享文本转换成可自行下载的视频、图片和实况资源，而不承担平台链接识别、作品信息解析和播放地址跳转处理。MediaLens 已完成 .NET 10 初始化，需要明确第一条抖音解析链路的接口、媒体契约和验证顺序；本次通过第一方匿名详情入口验证了四类公开样本的完整媒体，并完成独立客户端下载；不需要 Cookie、身份或本地签名。

## What Changes

- 先建立严格无 Cookie 的可行性验证，覆盖公开视频、普通图集、实况图集和混合图集，并验证调用方网络中的最终 CDN 下载。仅依据实际证据确认支持范围。
- 增加分享文本解析：提取首个受支持的链接、逐跳展开短链、识别抖音作品 ID，并将视频/图集链接统一交给作品解析流程。
- 增加匿名抖音适配：读取公开响应中的作品数据；在不构造身份或会话的前提下允许常规请求头及可验证的本地签名计算。无法取得数据时返回明确失败。
- 保留自动识别平台的 `POST /api/v1/resolve`，增加指定平台的 `POST /api/v1/platforms/{platform}/resolve`，两者共用请求体、解析管线和媒体结果契约；首期显式平台为 `douyin`。
- 增加 `GET /api/v1/platforms`，从内存适配器注册表返回已注册平台、启用状态和经验证的媒体能力；新增平台通过注册适配器扩展，不改变统一入口或引入数据存储。
- 解析响应固定为平台无关的作品、媒体项、下载候选三层模型，包含作品 ID/公开页、可空描述、顺序与实况配对；每个候选独立提供最终 CDN URL、完整必要请求头、可空格式/尺寸/时长/大小及过期信息。
- 明确统一的 `requestId`、字段类型和可空性、空列表/空字典语义，以及错误码、可重试标记和建议等待秒数；平台发现同样使用请求关联标识。
- 作品类型区分 `video` 与 `album`；媒体项区分 `video`、`image` 与 `livePhoto`，实况的静态图与动态短片保持在同一项中。
- 所有上游请求和重定向均不接收、生成、存储或发送 Cookie，不复用 `Set-Cookie`；不构造账号/游客身份，不引入身份池或浏览器会话回退。
- 增加 ASP.NET Core 10 Minimal API 宿主、共享解析组件、协议边界验证和 Linux 容器交付；允许先完成可独立验证的运行结构，生产适配器启用与成功声明仍须通过真实匿名可行性门槛。

非目标：服务端媒体下载、文件持久化、转码、账号登录、批量采集、作者列表、相册权限及系统原生实况照片封装；其他平台适配不属于本次变更。有限的响应读取用于解析元数据或解析媒体跳转，不构成媒体文件下载服务。

## Capabilities

### New Capabilities

- `share-text-resolution`：从分享文本提取受支持链接，约束重定向目标，识别抖音作品 ID，并拒绝不属于单个作品的资源。
- `cookie-free-douyin-resolution`：约束全部上游请求为严格无 Cookie，验证匿名元数据获取与最终 CDN 地址解析，明确可行性门槛和失败行为。
- `platform-routing`：定义统一解析、显式平台解析和平台发现路径，基于注册表分发并如实表达支持范围与版本兼容策略。
- `media-resolution-api`：定义共用的 Minimal API 契约、视频/图片/实况结果模型、资源完整性、下载请求头、过期信息及错误契约。

### Modified Capabilities

无。仓库当前没有已发布的规格或 API 契约。

## Impact

- 新增 OpenSpec 规格、可行性记录和后续的 .NET 10 解析/API 实现；沿用现有解决方案、共享构建配置及中文文档约定。
- 网络依赖限于经验证的抖音公开入口及返回媒体的受支持 CDN；不将现有两个参考项目的 Cookie、身份池、Browser RPC 或不透明 Token 服务作为运行依赖。
- 调用方负责流式下载、失效后重新解析、本地保存和相册集成。服务返回的是媒体资源及配对信息，不宣称已生成系统原生实况照片。
- 参考项目提供了 URL 规则与媒体字段映射的依据，但其会话解析流程不能证明本变更满足无 Cookie 要求。各媒体类型的成功验收必须以独立实测为准；明确失败响应不能替代该类型的成功验收。
