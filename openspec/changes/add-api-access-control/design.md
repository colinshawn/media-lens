## Context

当前 `Program.Main` 使用 .NET 10 的 `WebApplication.CreateBuilder`，注册共享解析服务后依次安装统一错误处理中间件和 API 路由。`MapMediaResolutionApi` 将两个 POST 与平台发现 GET 放在 `/api/v1` 路由组中；`UseApiErrors` 已生成请求标识、拒绝入站 Cookie、限制正文大小，并统一序列化错误。

现有 Docker 镜像设置 `ASPNETCORE_HTTP_PORTS=8080`，使用非 root 用户，也支持只读文件系统；应用没有密钥持久化目录。解析超时已通过 `MediaLens:ResolutionTimeoutSeconds` 配置，本变更保留该入口与原有取值范围。

本变更服务于能保管密钥的后端、脚本与自用调用方。共享 Bearer token 是本服务的访问凭证，与抖音、Bilibili 的账号、Cookie 或游客身份无关。本设计不声称能够证明网页域名或 App 身份。

## Goals / Non-Goals

**Goals:**

- 用一个部署时提供的共享 token 保护现有三个 API，并在解析业务之前拒绝未授权请求。
- 对外提供 `SECRET_TOKEN`、`HTTP_PORT`，保持 .NET 原生配置兼容和明确的启动失败行为。
- 复用现有静态 DTO、源生成 JSON、错误结构、请求标识及严格无 Cookie 传输，不新增服务依赖或持久化写入。
- 为调用方与容器升级提供可复现的迁移、测试与回滚步骤。

**Non-Goals:**

- 用户系统、JWT 签发与刷新、权限角色、多租户、多密钥、请求签名、防重放、IP 白名单或客户端完整性证明。
- 自动生成或保存 token、读取挂载的 Secret 文件、运行时热更新密钥、自动签发 TLS 证书。
- 在本次变更中引入限流配置、Redis、数据库、浏览器或媒体下载代理；限流可由部署入口或后续独立提案处理。
- 重命名既有解析超时环境变量，或改变平台能力、资源结构、图集顺序和实况配对。

## Decisions

### 1. 使用单个不透明 Bearer token

调用方通过单个 `Authorization: Bearer <token>` 请求头传递部署密钥。认证方案名按 HTTP 规则不区分大小写，token 内容按原值区分大小写；拒绝缺失、空值、错误方案、重复头部、多重凭证以及格式不合法的值。只从该请求头读取凭证，不从 URL、JSON、Cookie 或自定义备用头提取。

选用静态 token，是因为当前只需要共享调用资格，无需管理身份声明、签名密钥、签发服务与登录会话。配置值和入站 token 本体必须是 `32～256` 个 ASCII 字符，两个边界均包含在合法范围内，并符合 [Bearer token 的字符语法](https://www.rfc-editor.org/rfc/rfc6750.html#section-2.1)；ASCII 不是对全部 ASCII 字符的放行，空白、控制字符和其他语法不合法字符仍被拒绝。

长度按实际配置或传输的 token 字符串计数，不包含请求头中的 `Bearer ` 前缀，不按 Base64 解码后的字节数计算。合法 token 每个字符对应一个 ASCII 字节，因此字符数与传输字节数一致；禁止非 ASCII 字符，不对密钥进行大小写转换、裁剪或截断，不能通过规范化把越界或格式错误输入变为合法密钥。`32～256` 是本项目的输入约束，不是 Bearer 协议规定的统一长度。

部署方推荐使用 32 个安全随机字节生成密钥，例如编码为 64 字符十六进制或 43 字符无填充 Base64URL，均满足长度要求；程序不自动生成默认值。最小长度用于拦截过短配置，最大长度用于约束异常输入和误配置；长度不能证明随机强度，不以长度合规代替安全随机生成，也不新增基于字符重复率的强度判定。

启动时先验证最终选中配置的长度、ASCII 和 Bearer 字符语法，再固定配置快照；这些约束同样适用于原生环境变量、配置文件和命令行入口。入站校验先检查单头和 Bearer 结构，再检查 token 本体的长度与字符，只有合法输入才进行编码、摘要计算和比较。到达鉴权层的过短、过长或字符非法输入直接返回统一 `401 / UNAUTHORIZED`，不进入正文绑定或业务服务；HTTP 服务器及既有前置检查的拒绝行为仍按原规则执行。

校验实现使用固定时间比较，例如先对已通过格式校验的配置与入站 token 按一致的 UTF-8 编码计算 SHA-256，再使用 [CryptographicOperations.FixedTimeEquals](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.cryptographicoperations.fixedtimeequals?view=net-10.0) 比较固定长度摘要；摘要只存在内存中，不写日志或持久化。这里的散列仅用于本地比较，不构造任何平台签名、账号或游客身份。固定合成输入需要验证字节一致性、大小写差异与不匹配结果。

边界验收使用字符语法合法的合成 ASCII 输入：配置为 31 或 257 字符时必须在监听前非零退出，32 和 256 字符时必须允许启动；请求 token 与对应 32 或 256 字符配置完全一致时，平台发现请求返回 200，与配置不匹配时仍返回 401。对已正常启动的服务，31 和 257 字符的请求 token 必须在摘要计算前返回统一 401。另行覆盖字符数在范围内但包含非 ASCII、前缀不计入长度、不得裁剪/截断后通过等场景；全部用例仅使用合成值，日志和错误不包含原值。

密钥更换通过更新部署配置并重建或重启服务完成；本次不支持新旧密钥重叠有效期。选择这一方式维持无状态和只读容器，避免自动生成密钥后还需要持久化、恢复和安全分发的生命周期。

### 2. 对外变量作为明确的配置别名

| 对外环境变量 | 内部配置键 | 原生兼容入口 | 默认与校验 |
| --- | --- | --- | --- |
| `SECRET_TOKEN` | `MediaLens:Auth:SecretToken` | `MediaLens__Auth__SecretToken`、同名配置文件键或命令行键 | 无默认值；必须为 `32～256` 个符合 Bearer 语法的 ASCII 字符；最终选中的值缺失或不合法时启动失败 |
| `HTTP_PORT` | `HTTP_PORTS` | `ASPNETCORE_HTTP_PORTS`，以及框架支持的其他监听配置 | 别名仅接受一个十进制整数 `1`—`65535`；镜像默认 `8080` |

这两个名称是 MediaLens 的容器友好约定，不是 Docker 自动解释的通用变量。`SECRET_TOKEN` 与 `HTTP_PORT` 需要显式映射；不能假设将单下划线替换为冒号就能实现全部别名。环境变量使用文档中的大写名称。

对同一个内部配置键，来源顺序明确为：命令行 > 对外环境变量别名 > .NET 原生环境变量 > 配置文件 > 既有默认值。别名映射必须放在命令行配置之前，不能在完成配置后无条件追加覆盖命令行的内存值。未设置的别名不产生覆盖；选中的空值或非法值不能静默回退至较低来源。测试必须区分变量不存在、空字符串与全空格。

端口别名只映射 `HTTP_PORTS`，保留框架跨配置键的监听优先级：`ASPNETCORE_URLS`、`--urls` 或显式 Kestrel 端点仍按框架规则优先于端口列表。`HTTP_PORT=9000` 必须能覆盖镜像继承的 `ASPNETCORE_HTTP_PORTS=8080`；显式 `--urls` 仍有效，不强制重写为端口模式。只有实际选中的配置需要生效校验，低优先级值不能抢占已经选定的高优先级配置。

未提供端口别名时保留原生配置行为；镜像中的 `ASPNETCORE_HTTP_PORTS=8080` 继续提供容器默认端口。原生端口列表和 URL 配置继续使用框架语义，`HTTP_PORT` 本身不扩展为多端口、URL 或监听地址输入。非 Docker 运行也可使用同一别名，但本变更不改写框架在完全没有监听配置时的默认行为。

### 3. 在真实端点的请求绑定前统一鉴权

在 `/api/v1` 路由组上标记本服务鉴权元数据，在路由已匹配、端点委托尚未执行的位置安装轻量中间件；不把校验复制到各平台适配器，也不依赖绑定后才运行的端点过滤器。后续加入同一路由组的端点继承相同要求。

请求顺序为：生成 `requestId` 与统一错误范围 → 既有 Cookie/请求大小等前置检查 → 路由匹配与组级 token 校验 → JSON 绑定与输入验证 → 解析服务。沿用现有前置检查优先级：包含 Cookie 的请求仍返回 `400 / INVALID_INPUT`，已由前置检查判定正文过大的请求仍返回 `413`。对通过这些检查的受保护端点，缺少凭证时即使 JSON 不合法也先返回 `401`。

未知路径和不匹配的 HTTP 方法维持既有 `404`、`405` 及统一错误形状，不新增公开平台发现接口、健康端点或特殊鉴权旁路。鉴权失败后不能执行平台发现服务、解析器、适配器或任何上游请求。

### 4. 使用现有错误契约表达未授权

鉴权失败统一返回 `401 Unauthorized`、`WWW-Authenticate: Bearer`，JSON 仍为 `requestId` 与 `error`。新增稳定错误码 `UNAUTHORIZED`，使用通用消息，`retryable: false`、`retryAfterSeconds: null`；不向调用方透露是密钥不存在、内容不匹配还是内部比较失败。

统一错误映射需要显式支持 `401`，不能落入当前通用的 `INVALID_INPUT` 分支。有效 token 后的格式、平台、上游和取消错误继续走原有处理，不改变 v1 成功字段，也不新增 `data` 包装。

### 5. 凭证只留在 API 宿主

中间件读取入站鉴权头并完成比较，解析服务和共享 HTTP 客户端不接收该密钥。所有平台元数据、短链及媒体跳转的每一跳继续保持无 Cookie、无身份构造，也不得携带本服务的 `Authorization`；上游要求会话时继续明确失败。

响应候选的 `headers` 仍只来自已有常规下载头允许列表，不能包含本服务密钥、`Authorization`、`Proxy-Authorization`、Cookie 或上游账号凭据。现有最终 CDN URL、完整查询参数、独立下载头、图集顺序、混合项和实况静态图/短片配对全部保持。

启动错误只记录配置项名称和安全原因；请求日志只记录请求标识、状态与必要事件，不记录 token、Authorization 内容或其摘要。仓库与镜像只允许合成测试值或占位符，真实 token 必须在运行时注入。

### 6. 保持 Docker 端口发布与应用监听的职责

镜像继续使用非 root 用户和默认容器端口 `8080`，不声明内置 `SECRET_TOKEN`，不需要可写卷。`EXPOSE 8080` 是镜像说明，不会随 `HTTP_PORT` 自动更新，也不会自动发布宿主机端口。

若 `HTTP_PORT=9000`，应用在容器内监听 `9000`，Docker 的目标端口必须同时改为 `9000`，例如 `-p 127.0.0.1:8080:9000`。示例默认绑定宿主机回环地址；公网入口通过反向代理或部署平台提供 HTTPS，代理到容器的链路也应处于受控网络。文档明确 CORS 和网页内置共享密钥无法证明客户端来源。

中英文 README 提供 `--env-file` 或 Compose `environment` 示例，Compose 可使用 `${SECRET_TOKEN:?请配置 SECRET_TOKEN}` 提前拒绝漏配；应用仍负责最终配置校验，不能只依赖 Compose。示例必须区分 Compose 插值、容器内环境变量和 Docker `ports`，不要求提交真实 `.env` 文件。

## Risks / Trade-offs

- [共享 token 泄露后可被复用，无法绑定真实来源] → 密钥仅交给能保管它的调用方，公网使用 HTTPS，避免在公开前端内置，泄露后更换配置并重启；独立限流和更强身份机制另行设计。
- [新增必填 token 会中断旧部署与无请求头的调用方] → 标记为破坏性变更，先更新部署密钥与客户端请求头，平台发现探测也需要同步更新。
- [端口别名与原生 URL 配置混用导致预期不同] → 别名仅映射 `HTTP_PORTS`，保留原生 URL 优先级，用真实进程验证冲突组合并在文档中给出说明。
- [环境变量冲突或空值被误当成缺省] → 固定来源顺序，仅未设置表示回退；已选中的非法值在监听之前失败，错误不包含原值。
- [鉴权或日志改动破坏无 Cookie 和脱敏边界] → 以本地受控上游观察全部请求头与重定向，断言凭证不出现在出站请求、响应候选和捕获日志中。

## Migration Plan

1. 实现配置读取、启动校验、组级鉴权与错误映射；更新已有 HTTP 测试宿主，使用合成密钥运行回归。
2. 完成真实进程的缺失/非法配置、配置优先级、默认和自定义监听端口验证，并验证密钥配置及入站 token 的 `31、32、256、257` 字符边界、非 ASCII 拒绝、前缀不计数及不裁剪/截断；所有场景使用仓库外临时文件或合成配置。
3. 构建 Linux 镜像，分别验证漏配 token 非零退出、默认端口、自定义端口及发布映射、无凭证 `401`、有凭证平台发现、受控双平台 POST 和只读运行。公网真实样本如需复查，继续使用仓库外输入，区分 API 解析与客户端媒体下载证据。
4. 部署方预先生成并保管密钥，更新调用方与探测请求头，再更新镜像和运行环境。更换密钥时重启服务，不在日志公布密钥。
5. 回滚时恢复上一镜像及其部署配置；上一版本缺少该鉴权保护，只能在入口已通过网络隔离或反向代理访问控制限制后回滚，不能把去除 token 当作本版本的运行开关。
