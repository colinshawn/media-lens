# 分享文本解析规范

## Purpose

规定从公开分享文本选择受支持链接、匿名展开短链和提取作品标识的行为，限制解析资源范围，并通过完整特殊用途地址规则及逐跳目标校验防止访问非公开网络。

## Requirements

### Requirement: 从分享文本选择首个受支持链接

统一入口 SHALL 从非空分享文本按出现顺序提取首个已注册且启用适配器支持的链接，按平台注册规则支持抖音与经验证启用的 Bilibili；指定平台入口 SHALL 选择文本中首个属于指定适配器的链接。系统 MUST 处理包围链接的中文标点及可识别的无协议前缀链接，不隐式批量解析；输入或平台约束不满足时在平台网络请求前明确失败。 适配器 SHALL 先以无网络副作用的 CanHandle 识别平台归属，再在选定适配器内验证资源路径/标识/参数；归属识别不授权网络目标访问，也不因选中资源失败而回退到文本中的另一链接。

#### Scenario: 文案包含短链和中文标点
- **WHEN** 分享文本包含说明、口令及被中文标点包围的抖音短链
- **THEN** 系统提取正确 URL，不把周围文案或标点作为 URL 的一部分

#### Scenario: 文本包含多个链接
- **WHEN** 文本包含一个不受支持的链接及两个受支持的抖音链接
- **THEN** 系统仅选择最先出现的受支持抖音链接，不发起批量解析

#### Scenario: 没有有效文本或 URL
- **WHEN** 文本为空、超出输入限制或不包含 URL
- **THEN** 系统返回 `INVALID_INPUT`，不发起平台请求

#### Scenario: 统一入口只有未支持平台链接
- **WHEN** 文本包含 URL，但没有已注册且启用适配器支持的链接
- **THEN** 系统返回 `PLATFORM_NOT_SUPPORTED`，不尝试未知平台请求

#### Scenario: 指定入口包含不同平台的链接
- **WHEN** 指定抖音平台的文本包含其他平台链接及一个抖音链接
- **THEN** 系统选择首个抖音链接；若没有抖音链接，则返回 `PLATFORM_MISMATCH`，不切换到其他适配器

#### Scenario: 双平台文本按入口约束选择
- **WHEN** 文本同时包含 Bilibili 和抖音链接，且两者均已验证启用
- **THEN** 统一入口选择文本中最先出现的受支持链接，指定平台入口选择首个属于该平台的链接，不受注册顺序影响

#### Scenario: Bilibili 分享文本中的短链
- **WHEN** 文本包含被中文标点包围的 b23.tv 链接或可识别的无协议完整视频链接
- **THEN** 正确提取链接并交给 Bilibili 规则，保持短链大小写，不隐式处理其他链接或批量作品

#### Scenario: 已识别平台中的未支持资源
- **WHEN** 已启用 Bilibili 的所属链接指向主页或直播，而非本次支持的视频
- **THEN** 选择归属平台后本地返回 UNSUPPORTED_RESOURCE，不误报 PLATFORM_NOT_SUPPORTED/PLATFORM_MISMATCH，也不请求该资源或回退到文本中后续作品

#### Scenario: 已选链接参数无效
- **WHEN** 首个已启用平台所属视频链接的 p 无效，且文本后面还有合法视频链接
- **THEN** 保留首链接选择并返回 INVALID_INPUT，不跳过它解析后续作品

### Requirement: 无 Cookie 地逐跳展开短链

系统 MUST 手动处理有限次数的 HTTP(S) 重定向，正确解析相对 `Location`，并在每一跳验证允许的平台/媒体目标与公开网络地址。全部跳转 SHALL 不发送 Cookie、不复用 `Set-Cookie`、不构造账号或游客身份；无法匿名展开时 MUST 明确失败。

#### Scenario: 相对地址与多跳短链
- **WHEN** 短链经过绝对或相对 `Location` 跳转到完整作品链接
- **THEN** 系统逐跳取得最终作品链接，且任一请求都不包含 Cookie

#### Scenario: 上游在跳转中设置 Cookie
- **WHEN** 首跳响应包含 `Set-Cookie` 并返回下一跳
- **THEN** 下一跳仍不发送 Cookie，且不建立会话或身份作为重试条件

#### Scenario: 越界或无法完成的跳转
- **WHEN** 跳转目标包含 URL 凭据、指向非公开地址/未允许域名，或出现循环、超限、无有效目标
- **THEN** 系统终止解析并返回明确错误，不访问被拒绝的目标

### Requirement: 依据完整特殊用途地址快照分类公网目标

系统 MUST 使用有来源和获取日期的 IANA IPv4、IPv6 特殊用途地址注册表快照进行本地分类，优先匹配最具体的前缀。特殊用途条目仅在目的地址有效、可转发且明确可全球到达时允许；False、N/A、空值及废弃条目 MUST 拒绝。系统 SHALL 拒绝多播、带接口区域编号的地址及尚未识别为全球单播的 IPv6 空间；该判断不代表实际网络可达性。

#### Scenario: 父网段拒绝但特定子网允许
- **WHEN** 地址同时命中拒绝的父网段和 IANA 明确允许的更具体条目
- **THEN** 使用最长前缀结果，例如允许 192.0.0.9/32 和 2001:1::1/128，不依赖规则排列顺序

#### Scenario: IPv6 特殊用途或废弃转换机制
- **WHEN** 地址属于基准测试、文档、私有、链路本地、废弃或未明确全球可达的特殊用途网段
- **THEN** 拒绝连接，包括 2001:2::/48、3fff::/20、Teredo 和 6to4 等当前快照中的相应条目

#### Scenario: IPv4 嵌入 IPv6
- **WHEN** 地址是 IPv4-mapped IPv6，或使用标准 NAT64 前缀 64:ff9b::/96
- **THEN** 内嵌 IPv4 必须通过同一 IPv4 规则，不能借外层 IPv6 形式访问本机、内网、云元数据或其他受限地址

#### Scenario: DNS 混合返回公网与受限地址
- **WHEN** 同一目标的 DNS 结果中任意一个 IPv4 或 IPv6 地址未通过分类
- **THEN** 拒绝整个目标，并且成功路径只连接已验证的 IP，不在连接时再次解析域名

### Requirement: 识别作品 ID 并限制资源范围

系统 SHALL 按所选平台注册的规则识别作品。抖音继续识别受支持的 `/video/`、`/note/`、`/slides/` 及展开路径，优先使用 `modal_id`、`vid`；Bilibili 识别 BV/AV 完整视频链接及 b23.tv 展开结果，p 缺省为 1，显式 p 必须是唯一且有效的正整数并在取得 pages 后验证范围。作品 ID MUST 为字符串，BV 主体大小写保持不变。Bilibili 只解析选定分 P，其未实现的主页、合集、直播、番剧、互动及图文等资源 SHALL 返回 `UNSUPPORTED_RESOURCE`；抖音既有视频、图集、实况与非作品资源判定保持原有行为。

#### Scenario: 主页路径上打开的作品
- **WHEN** 公开链接为用户主页路径并携带有效 `modal_id`
- **THEN** 系统选择该作品 ID，不把输入转为作者列表解析

#### Scenario: 图集与分享路径
- **WHEN** 完整链接或短链展开结果为受支持的视频/图集分享路径
- **THEN** 系统提取对应作品 ID，以作品信息响应确认最终媒体类型

#### Scenario: 不支持的资源与大整数 ID
- **WHEN** 链接仅指向作者主页、合集或其他非单作品资源
- **THEN** 系统返回 `UNSUPPORTED_RESOURCE`，不枚举其作品；任何已提取作品 ID 均不得转换为可能丢失精度的数值

#### Scenario: Bilibili BV 与 AV 链接
- **WHEN** 输入是合法 BV/AV 视频完整链接，或短链展开到该类链接
- **THEN** 按 Bilibili 规则取得标识并核对上游作品身份，AV 规范化为可信详情中的 BV，不套用抖音数字 ID 规则

#### Scenario: 默认 P 与显式 P
- **WHEN** Bilibili 链接省略 p，或提供有效且未越界的 p
- **THEN** 分别只选择第 1 P 或指定 P，规范 webUrl 明确保留该选择，不把多个分 P 当备用 URL

#### Scenario: 无效或越界 P
- **WHEN** p 为空、零、负数、小数、溢出、重复，或超过实际 pages 数量
- **THEN** 返回 INVALID_INPUT，不批量解析或悄悄回到首 P

#### Scenario: 跨平台短链展开
- **WHEN** 指定平台的短链 Location 指向另一个已注册平台
- **THEN** 在发起跨平台目标请求前返回 PLATFORM_MISMATCH，不借另一个平台已注册而放行
