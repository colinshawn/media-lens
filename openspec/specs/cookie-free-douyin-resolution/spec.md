# 严格无 Cookie 抖音解析规范

## Purpose

规定抖音公开作品的严格匿名解析边界，确保元数据、短链及媒体跳转均不使用 Cookie 或身份构造，返回完整最终媒体地址，并以脱敏的真实样本验证明确支持范围。

## Requirements

### Requirement: 全部上游访问保持严格无 Cookie

系统 MUST 不接收、生成、存储或发送 Cookie，不转发调用方 Cookie、不复用上游 `Set-Cookie`。元数据、短链、播放跳转及其后续请求 SHALL 使用相同约束；系统 MUST 不创建账号/游客身份、身份池或浏览器会话回退。

#### Scenario: 禁止调用方身份输入
- **WHEN** API 请求包含 `Cookie` 请求头或 `cookie`、`session`、`identity` 身份输入字段
- **THEN** 系统返回 `INVALID_INPUT`，不使用这些值请求上游

#### Scenario: 同一次解析及不同调用间的 Cookie 隔离
- **WHEN** 上游任意响应设置 Cookie，且随后发生重定向或另一次解析
- **THEN** 全部后续上游请求仍无 Cookie，返回调用方的响应也不包含上游 `Set-Cookie`

#### Scenario: 上游要求建立会话
- **WHEN** 元数据入口或播放入口要求 Cookie、登录或游客身份才能继续
- **THEN** 系统返回 `COOKIE_FREE_UNAVAILABLE`，不调用会话、身份或浏览器生成服务回退

### Requirement: 依据匿名响应获取作品信息

系统 SHALL 只使用严格匿名请求实际取得的公开作品数据构建媒体结果。常规请求头与本地签名计算 MUST 不依赖身份/会话构造；协议字段不足或不可识别时 MUST 返回准确失败，不推测媒体地址或成功类型。

#### Scenario: 匿名响应包含完整作品数据
- **WHEN** 已验证的公开入口无 Cookie 地返回作品及媒体数据
- **THEN** 系统根据实际响应识别类型并提取视频、图片及每张实况的动态片段

#### Scenario: 页面可访问但媒体不可得
- **WHEN** 页面返回成功状态但仅包含空数据、会话要求或没有媒体信息
- **THEN** 系统返回 `COOKIE_FREE_UNAVAILABLE`，不把页面可访问等同于媒体解析成功

#### Scenario: 响应结构变化或作品明确不可用
- **WHEN** 响应结构无法识别，或上游明确报告作品删除/不可访问
- **THEN** 系统分别返回 `UPSTREAM_CHANGED` 或 `CONTENT_UNAVAILABLE`，不把任意拒绝响应推断为作品删除

### Requirement: 本地签名保持可验证的输入与字节一致性

若匿名入口需要本地签名，系统 SHALL 固定并验证 Query/Body 字节、参数顺序、字符编码、整数语义、时间及随机输入；MUST 保持被签名内容与实际发送内容一致。依赖 Cookie、游客身份档案、浏览器 SDK 会话或不透明远程 Token 数据的流程 SHALL 不作为满足本能力的实现。

#### Scenario: 固定输入复现签名
- **WHEN** 使用相同请求字节、常规头部、时间和随机输入运行已选定版本的本地算法
- **THEN** 结果与该版本的参考向量一致，且网络层不再次修改签名所覆盖的内容

#### Scenario: 算法需要身份材料
- **WHEN** 签名所需输入只能通过构造游客身份、Cookie 或浏览器会话取得
- **THEN** 系统将该路线判定为不符合约束，不以此开启平台支持

### Requirement: 输出最终 CDN 媒体地址

系统 SHALL 将必要的播放接口跳转解析为可下载的最终媒体 URL，并保留全部路径与查询参数。每一跳 MUST 校验目标并保持无 Cookie、无身份构造；可以有限读取响应头确认媒体，不提供媒体代理或文件持久化。成功响应 MUST 不把分享页、HTML 挑战页或未展开播放接口当作 CDN 文件地址。

每个必需图片或短片 SHALL 按候选优先级探测，在首个来源通过验证后立即停止并仅返回该来源。候选失败 SHALL 尝试后续候选；图集项与实况的图片/短片 MUST 全部保留，不以已有其他媒体成功为由返回部分作品。

#### Scenario: 首个来源可用而备用 CDN 无响应
- **WHEN** 同一必需媒体的首个候选已经通过状态、媒体类型及最终 CDN 验证
- **THEN** 返回该来源且不连接后续备用地址，不因备用超时增加解析等待

#### Scenario: 候选是直接媒体地址
- **WHEN** 候选地址已由受支持规则与响应证据确认为最终 CDN 媒体地址
- **THEN** 系统原样保留完整 URL，并提供与该地址匹配的必要下载请求头

#### Scenario: 播放接口跳转到 CDN
- **WHEN** 候选地址是需要继续跳转的播放接口
- **THEN** 系统无 Cookie 地解析每一跳并返回最终媒体 URL，不下载或存储媒体正文

#### Scenario: 必需媒体无法取得最终地址
- **WHEN** 必需资源没有可用候选、跳转需身份，或最终响应是非媒体内容
- **THEN** 系统返回 `MEDIA_INCOMPLETE` 或有会话要求依据的 `COOKIE_FREE_UNAVAILABLE`，不返回完整成功结果

### Requirement: 双栈快速回退与独立阶段时限

API 与 Probe 的共享 HTTP 传输 SHALL 在完整验证本次 DNS 结果后交替尝试 IPv4/IPv6，默认间隔 300 ms 启动后续连接，明确失败时立即回退，成功或取消时释放其他尝试。MUST 固定已验证的 IP 建连，不再次解析主机。DNS/TCP、TLS、响应头和元数据正文 SHALL 分别使用默认 15、15、30、30 秒预算，并受调用方取消及既有总时限约束；媒体不读取正文。阶段超时 MUST 作为临时上游故障处理，仅总时限真正到期时返回 `RESOLUTION_TIMEOUT`。

#### Scenario: 一个地址族无法建立连接
- **WHEN** 允许主机的首个已校验 IP 挂起，而另一地址族的地址可达
- **THEN** 在默认 300 ms 后启动另一地址族连接，无需等待首个尝试耗尽建连时限，成功后回收落选连接

#### Scenario: TLS 或响应头等待超时
- **WHEN** 总时限尚未到期，但某个 HTTP 阶段超过自己的预算
- **THEN** 记录固定超时阶段，并尝试该媒体的下一候选；必需媒体仍无可用来源时返回可重试的 `UPSTREAM_UNAVAILABLE`

### Requirement: 用真实样本确认支持范围

系统的实现与支持声明 MUST 以公开视频、普通图集、实况图集、混合图集的逐类实测为依据，并记录全部跳转无 Cookie、完整媒体/配对、最终 CDN 和调用方下载结果。未验证或失败类型 SHALL 保持未通过；仅正确返回错误 MUST 不算该媒体类型的成功验收。

#### Scenario: 全链路通过
- **WHEN** 某类真实公开样本在无 Cookie 条件下取得完整资源，且独立客户端使用返回 URL/头部成功下载
- **THEN** 该类型才能记录为已验证支持，证据包含时间、响应分类及可复现步骤

#### Scenario: 替身通过而平台验证未通过
- **WHEN** 离线协议测试通过，但真实样本被要求会话或未取得完整资源
- **THEN** 保留该类型未通过状态并记录失败依据，不以替身测试或公开页面可见性宣称支持

### Requirement: 真实验证输入不得进入代码库

用户提供的真实分享文本和链接 MUST 只从仓库外文件传入。代码、测试夹具、文档和提交记录 MUST 不包含这些输入、由其提取的作品 ID、完整重定向地址或媒体 URL；仓库内 SHALL 仅保存合成夹具与不包含样本标识的验证结果。

#### Scenario: 运行真实样本验证
- **WHEN** 开发者传入仓库外的样本文件执行验证
- **THEN** 工具仅输出类别、入口、主机、状态码、Cookie 是否出现和结构统计，不回显原始输入、作品 ID、原始响应或媒体 URL

#### Scenario: 编写可重复的协议测试
- **WHEN** 新增分享提取、媒体结构或 HTTP 行为测试
- **THEN** 测试使用合成链接、标识和本地 HTTP 替身，不把用户提供的链接固化为测试用例
